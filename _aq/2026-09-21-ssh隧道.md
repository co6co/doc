> 本文是一篇 SSH 隧道实战指南，核心解决「如何让公网访问内网服务」的问题。文章从服务器 sshd 配置入手，讲解反向隧道（`-R`）的建立方法，再通过 `autossh` + `systemd` 实现断线自动重连的长期稳定方案，最后补充 `-L` 正向隧道与 `-D` 动态转发的扩展用法。全文配有可直接复制的命令与配置文件，适合需要远程访问内网服务的开发者参考。

# 1. 服务器 sshd 配置

```config
GatewayPorts clientspecified # 允许反向转发绑定到非本机地址
AllowTcpForwarding yes
# 可选：保活，配合客户端
ClientAliveInterval 30
ClientAliveCountMax 3
```

- GatewayPorts
  - no（默认） 反向端口只绑 127.0.0.1
  - clientspecified 由客户端用 -R 0.0.0.0:端口:... 或 -R 公网IP:端口:... 决定绑哪里，最灵活
  - yes：所有反向端口默认绑 0.0.0.0

- 后面的可选参数
  - ClientAliveInterval 每 30 秒探测一次
  - ClientAliveCountMax 最多探测 3 次无响应就断开
    时间线示例（假设客户端突然断网）：
  1.  T+0s：客户端断网，连接实际上已经不通了。
  2.  T+30s：服务器发第 1 次探测，无响应。
  3.  T+60s：服务器发第 2 次探测，无响应。
  4.  T+90s：服务器发第 3 次探测，无响应。
  5.  T+90s+：服务器判定客户端已死，主动关闭 TCP 连接，释放文件描述符和端口。

## 1.1 保活参数配置说明`ssh -R` 反向隧道场景中如果不配保活:

- 局域网机器网络闪断、或者 NAT 超时回收了连接，SSH 连接就会变成“半开连接”（TCP 状态还在，但实际已不通）
- 服务器端以为隧道还在，端口还占着，但实际流量过不去
- 客户端 ssh 进程可能也卡死，不会主动退出，autossh 也就没法检测到失败并重连

配上这两个参数后:

- 服务器端能在 90 秒​ 内发现连接已死，主动断开
- 客户端 ssh 进程收到断开信号（或写 TCP 时发现 RST）也会退出
- autossh 检测到进程退出，就会按 `RestartSec` 自动重连，隧道恢复

重启ssh服务

```
sudo systemctl restart sshd   # 有的发行版是 ssh
```

## 2. 局域网机建立反向隧道```

ssh -N -R 0.0.0.0:18080:127.0.0.1:8080 tunnel@1.2.3.4

# 只允许服务器使用访问

ssh -N -R 127.0.0.1:18080:127.0.0.1:8080 tunnel@1.2.3.4

# 一次可以建立多个反向代理

```
ssh -N \
  -R 0.0.0.0:18080:127.0.0.1:8080 \
  -R 0.0.0.0:15432:127.0.0.1:5432 \
  tunnel@1.2.3.4
```

- -R 远程转发：公网绑定地址:公网端口:内网目标host:内网端口
- -N 不执行命令，只做隧道
- 加 -f 可后台运行
- 如果端口不是默认端口使用 `-p` 参数

在任意外网机器 curl http://1.2.3.4:18080 应该回到内网 8080

## 3. 长期稳定：autossh + systemd

```
# Debian/Ubuntu
sudo apt install autossh
# EL
sudo yum install autossh   # 或 dnf
```

## 3.1 先配免密（autossh 后台重连不能交互输密码）

### 3.1.1 生成密钥

```
# 局域网机
ssh-keygen -t ed25519 # 生成  /root/.ssh/id_ed25519.pub
ssh-copy-id tunnel@1.2.3.4
```

可选 创建通道相关用户，不用使用交互账号,
复制公钥时你需要用交换账号` /bin/bash`

```
# 在远程服务器上（用 root 或有 sudo 权限的用户）
sudo useradd -m -s /bin/bash tunnel
# 或者（某些系统）
sudo adduser tunnel

# 可选：禁止该用户交互登录，只能做端口转发（更安全）
sudo usermod -s /usr/sbin/nologin tunnel
# sudo usermod -s /bin/bash tunnel
# 或者在 sshd_config 里限制：
# Match User tunnel
#   AllowTcpForwarding yes
#   X11Forwarding no
#   PermitTTY no
```

### 3.1.2 手动保活测试

```
autossh -M 0 -N \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -o ExitOnForwardFailure=yes \
  -R 0.0.0.0:18080:127.0.0.1:8080 \
  tunnel@1.2.3.4
```

- `-M 0`：关掉 autossh 单独监控端口，用 SSH 自身 keepalive。
- `ExitOnForwardFailure=yes`：端口建不上就退，让 systemd/autossh 重拉。

### 3.1.3 做成 systemd

在局域网机 `/etc/systemd/system/reverse-tunnel.service` 创建服务配置文件（文件名可根据需要自己取）：

```
[Unit]
Description=Reverse SSH tunnel to public server
After=network-online.target
Wants=network-online.target

[Service]
User=tunnel
Environment=AUTOSSH_GATETIME=0
ExecStart=/usr/bin/autossh -M 0 -N \
  -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
  -o ExitOnForwardFailure=yes \
  -i /home/tunnel/.ssh/id_ed25519 \
  -R 0.0.0.0:18080:127.0.0.1:8080 \
  tunnel@1.2.3.4
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

### 3.1.4 开启服务

```
sudo systemctl daemon-reload
sudo systemctl enable --now reverse-tunnel
journalctl -u reverse-tunnel -f   # 排错
```

## 4. 扩展知识ssh 处理上面的 `-R` 反向隧道用法，还有两种 `-L` 正向隧道及 `-D` SOCKS 代理用法；

## 4.1 正向隧道（-L）

`-L = Local Port Forwarding`（本地端口转发）

> 在你执行 ssh 命令的这台机器上开一个端口，把所有连到这个端口的流量，通过 SSH 加密隧道，转发到 SSH 服务器能访问到的任意目标（可以是服务器自己，也可以是服务器网络里的其他机器）。

用法：

```
ssh -N -L [本地绑定地址:]本地端口:目标地址:目标端口 用户@SSH服务器

```

流量方向：
你的应用 → 本地端口 → SSH隧道 → SSH服务器 → 目标地址:目标端口

## 4.1.1 使用场景

场景 1： 把远程服务器的内网服务“拉”到本地
比如：比如公网机 1.2.3.4 上跑了一个 8080 的 Web 服务，但你不想直接开放 8080 到公网（安全考虑），只想自己本地访问

```
ssh -N -L 127.0.0.1:18080:127.0.0.1:8080 user@1.2.3.4
```

然后本地浏览器打开 http://127.0.0.1:18080 → 实际访问的是公网机上的 127.0.0.1:8080

主要用途：**安全地管理远程服务器上的 Web 管理后台、数据库 Admin UI 等，不用暴露端口到公网**

## 4.2 -L 与 -R 对比

| 特性         | -L（正向/本地转发）         | -R（反向/远程转发）           |
| ------------ | --------------------------- | ----------------------------- |
| 端口位置     | 本地开端口                  | 远端开端口                    |
| 流量方向     | 本地 → 隧道 → 服务器 → 目标 | 远端 → 隧道 → 本地 → 目标     |
| 目的         | 把远程资源“拉”到本地用      | 把本地/内网服务“推”到远端暴露 |
| 典型场景     | 安全访问远程内网服务        | 将内网服务暴露到公网          |
| 执行命令位置 | 想访问服务的那台机器        | 拥有服务的那台机器            |

和 -R 一样，-L 隧道断了也不会自动重连，也需要 autossh 保活。

记忆方式：

- -L：Local → 本地开端口，拉远程资源
- -R：Remote → 远端开端口，推本地资源

## 4.3 动态转发（-D）

-D 是 SOCKS5 代理，不算正向也不算反向，是“万能隧道”

```
ssh -N -D 127.0.0.1:1080 user@1.2.3.4
```

本地浏览器/应用配 SOCKS5 代理 127.0.0.1:1080，所有流量都走 SSH 服务器出去，相当于一个加密的“跳板代理”

---

## 5. 总结

本文完整介绍了如何通过 SSH 反向隧道将内网服务安全地暴露到公网，并保证长期稳定运行：

- **服务器端配置**：开启 `GatewayPorts clientspecified` 与 `AllowTcpForwarding`，并配置 `ClientAliveInterval` / `ClientAliveCountMax` 保活参数，让服务器能及时发现死连接。
- **反向隧道建立**：使用 `ssh -R` 将内网端口映射到公网服务器，支持一次建立多条隧道。
- **长期稳定运行**：通过 `autossh` + `systemd` 实现断线自动重连，配合免密登录确保后台无人值守运行。
- **扩展知识**：`-L` 正向隧道用于将远程服务拉到本地安全访问，`-D` 动态转发则提供 SOCKS5 代理能力。
