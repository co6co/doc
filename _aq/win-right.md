# 1. 守护进程
## 1.1 可能具备的特征
- 内核级驱动保护
  有一个内核驱动在时刻监控并守护这个进程，一旦检测到进程被结束，会立刻启动它。
- 系统服务关联
  进程本身是一个高权限的系统服务，受系统保护
- 进程保护机制
  进程本身被标记为受保护进程，普通工具无法终止。

## 1.2 查看
a. 服务的‘停止按钮’灰色或者停止后又立刻自动重启，说明它被驱动或策略锁定了。
b. 使用系统工具禁止自动启动。

# 1. 病毒
杀毒软件的可见性：无处遁形

正如我们之前讨论的，杀毒软件必须向系统注册服务、创建进程、占用资源。它的每一个动作都在系统的眼皮底下。

它的进程名（如 HipsDaemon.exe）、服务名、驱动文件名都是公开的，攻击者可以轻易地针对这些已知目标进行研究、hook 或攻击。

病毒的隐蔽性：潜入深海

- 无文件攻击：现代高级恶意软件越来越多地采用“无文件”技术。它们不将恶意代码写入磁盘成为可执行文件，而是直接注入到合法的系统进程（如 svchost.exe, explorer.exe）的内存空间中运行。杀毒软件很难区分哪些是合法代码，哪些是注入的恶意代码。

- 进程伪装与注入：病毒可以将自己的代码注入到杀毒软件自身的进程中。当它运行在杀毒软件的进程空间内时，杀毒软件的反病毒引擎甚至会将其视为“自身代码”而放行。

- Rootkit 技术：Rootkit 能够隐藏文件和进程。对于用户和管理员来说，那个正在疯狂攻击杀毒软件的恶意进程根本就是“不存在”的。

结论：杀毒软件是在明处作战，而高级病毒是在暗处偷袭。

## 1.2 攻击手段多样
关闭对于病毒来说，这只是众多攻击手段中最笨的一种。更高级的攻击是“欺骗”和“接管”。
a. DLL 注入与 API Hook
病毒不需要关闭杀毒软件，它可以修改杀毒软件调用的系统函数。例如，当杀毒软件试图扫描一个文件时，病毒可以劫持这个扫描请求，然后返回一个“一切正常”的假结果。对于杀毒软件来说，它“以为”自己完成了工作，但实际上什么都没做。
b. 利用零日漏洞
杀毒软件本身也是软件，它也存在未被发现的漏洞（零日漏洞）。攻击者可以利用这些漏洞，直接向杀毒软件进程发送精心构造的数据包，导致其崩溃或执行恶意代码，而无需知道其具体的关闭方法。
c. 社会工程学
这是最简单也最有效的方式。病毒会弹出一个伪造的“Windows 更新”或“系统错误”窗口，诱导用户自己点击“允许”或“同意”，从而授予病毒管理员权限，让它可以为所欲为。

好比：
杀毒软件就像一个公开的警察局。
它有固定的地址（注册表项）、公开的警车（进程）、明确的规章制度（权限模型）。坏人（病毒）可以很容易地知道警察局在哪里，研究它的巡逻路线（行为模式），甚至收买内部的警员（利用漏洞）。

高级病毒就像一群训练有素的特种兵。他们可以提前潜伏在警察局大楼的地基里（Bootkit），或者穿上警服混进警察队伍（进程注入），甚至可以切断警察局的对外通讯（DLL Hook），让警察无法呼叫支援。

所以，不是病毒“轻易”关闭了杀毒软件，而是病毒利用了其在攻击链上的先天优势（先发、隐蔽、多样），绕过了或瘫痪了杀毒软件的防御体系。

# 2. 现在安全
- UEFI 安全启动 (Secure Boot)

原理：这是硬件和操作系统联手打造的“第一道防线”。主板的 UEFI 固件内置了一个受信任的证书颁发机构（CA）。只有那些带有微软（或其他可信机构）数字签名的操作系统引导程序（如 bootmgfw.efi）才能被加载。

作用：如果一个 Bootkit 没有有效的数字签名，它会在启动的最初阶段就被 UEFI 固件直接拒绝，根本没机会接触硬盘。这就好比机场的安检，没有登机牌（有效签名）连候机楼都进不去。 

- 驱动程序强制签名 (Driver Signature Enforcement)

原理：Windows 要求所有在内核层运行的驱动程序都必须经过微软的 WHQL（Windows Hardware Quality Labs）认证并签名。

作用：这堵住了病毒通过加载一个恶意驱动来实现 Rootkit 的途径。没有微软签名的驱动，系统会直接拒绝加载。

- 基于虚拟化的安全 (VBS) 与 受信任的平台模块 (TPM)

原理：这是更底层的防护。系统将最核心的部分（如凭据存储、代码完整性检查）放在一个由 CPU 硬件支持的、与普通操作系统隔离的“安全飞地”中运行。

作用：即使操作系统内核被 Bootkit 或 Rootkit 攻破，这个“安全飞地”内的代码和数据仍然是安全的，不会被窃取或篡改。

- 内存扫描与引导扇区监控

原理：即使 Bootkit 侥幸通过了 Secure Boot，安全软件也可以在操作系统启动后，立即对内存和硬盘引导扇区进行深度扫描，寻找已知的 Bootkit 特征码或异常行为模式。

## 2.1 Rootkit 
恶意Bootkit 的首要任务是加载并激活一个内核级的 Rootkit。这个 Rootkit 会：
- 挂钩系统函数：修改内核的关键函数，使得后续加载的任何驱动或程序都无法察觉到它的存在。
- 隐藏自身：确保你在任务管理器、注册表编辑器等工具中看不到 Bootkit 和 Rootkit 的相关文件、进程和服务。
- 加载下一阶段的恶意软件：例如，它会加载一个完整的木马、勒索软件或间谍软件，并将其注入到即将启动的操作系统进程中。
- 禁用后续安全检查：它可能会修改 Windows 的启动配置，确保在操作系统启动后，即使你手动重新开启 Secure Boot，也无法生效，或者会让系统在下次启动时跳过 Secure Boot 的检查。
- 移交控制权：
  在完成上述所有准备工作后，Bootkit 才会将控制权移交给真正的 Windows Boot Manager，启动操作系统。至此，你的电脑看起来一切正常，但实际上已经被完全控制，并且在操作系统层面没有任何防御措施能检测到 Bootkit 的存在。

## 2.2 UEFI和rootkit
早期：
- 开机。
- BIOS 自检 (POST)。
- 从硬盘的第一个扇区（称为 MBR，Master Boot Record）读取引导代码并执行。
- MBR 中的代码再加载硬盘分区里的操作系统引导程序（如 NTLDR 或 bootmgr）。
Bootkit 的诞生：正因为 BIOS 如此简单，攻击者发现了巨大的漏洞。他们可以轻松地编写一个恶意程序，覆盖掉 MBR 中的原始引导代码。当电脑启动时，BIOS 会毫不犹豫地执行这个恶意代码。这个恶意代码就是最早的 Bootkit。它可以在操作系统（如 Windows XP/Vista）启动之前就获得控制权，并随后加载一个修改过的操作系统内核，从而实现对整个系统的完全控制。在这个时期，Bootkit 非常流行，因为 BIOS 没有提供任何安全机制来验证 MBR 代码的来源是否可信。

UEFI 的出现：一道新的防线
为了解决 BIOS 的诸多缺陷（包括安全问题），业界推出了 UEFI (Unified Extensible Firmware Interface)​ 作为新一代的固件标准。

UEFI 的安全机制：
- Secure Boot (安全启动)：这是 UEFI 最核心的安全特性。它引入了一个受信任的证书颁发机构 (CA)​ 链条。简单来说，UEFI 固件里内置了一个 Microsoft 的证书（以及其他 OEM 的证书）。只有那些带有有效数字签名的操作系统引导程序（如 bootmgfw.efi）才能被 UEFI 加载和执行
- 启动流程的改变：UEFI 不再直接从 MBR 启动，而是从一个专门的 EFI 系统分区 (ESP)​ 中寻找引导程序。这个分区里的文件同样需要经过签名验证。

Bootkit 的演变：面对 UEFI 的挑战，Bootkit 并没有消失而是变得更加复杂和隐蔽
攻击 
- Secure Boot 本身：这是最有效的方法，也就是我们之前讨论的——关闭 Secure Boot。如果攻击者能物理接触到电脑并进入 UEFI 设置，将 Secure Boot 禁用，那么 UEFI 的安全链条就断裂了，Bootkit 就可以像在 BIOS 时代一样自由地感染 MBR 或 ESP 分区。
- 利用“安全启动”的例外：UEFI 为了兼容性，允许在 Secure Boot 开启的情况下，加载一些“不安全的”引导程序，例如用于系统恢复或旧版操作系统的引导程序。Bootkit 可能会伪装成这些被允许的引导程序。
- 固件级 Rootkit：这是最顶级的 Bootkit，它们不感染 MBR 或引导文件，而是直接将自己写入到 UEFI 固件芯片中。这样，无论你如何重装系统、更换硬盘，只要固件还在，Bootkit 就永远存在。这种攻击需要极高的技术水平，通常与国家级的 APT (高级持续性威胁) 组织有关。
## 专门的反 Rootkit 工具
- Windows Defender Offline：这是微软官方提供的离线杀毒工具。你可以从一台干净的电脑上下载它，刻录到 U 盘上，然后用这个 U 盘启动被感染的电脑。它会在 Windows 启动之前运行，从而有机会扫描和清除 Bootkit。

- Kaspersky Rescue Disk：卡巴斯基的救援盘，功能非常强大，原理和 Windows Defender Offline 类似，也是一个基于 Linux 的急救环境，可以在系统启动前扫描和清除恶意软件。

- Malwarebytes Anti-Rootkit (MBAR)：一款专业的反 Rootkit 工具，可以在 Windows 安全模式下运行，深入扫描系统内核，寻找被隐藏的恶意程序。

- GMER：一款老牌的、功能强大的反 Rootkit 工具，以其能够检测内核级隐藏的进程、线程、模块和注册表项而闻名。但它需要一定的专业知识来解读扫描结果。

## UEFI与Bootkit
- UEFI 固件​ 是门卫，它手里有一份可信赖的名单（受信任的 CA 证书）。

- bootmgfw.efi​ 是持有有效邀请函的访客，门卫（UEFI）通过核对名单（验证数字签名）确认其身份后，才允许其进入（执行）。

- Bootkit​ 是没有邀请函的闯入者，门卫会直接将其拒之门外。

但是，这个安全链条可以被打破：
- 如果门卫（UEFI）的名单（受信任的 CA）被篡改了，或者门卫被收买了被感染），那么即使是没有邀请函的闯入者（Bootkit）也能大摇大摆地进来。
- 如果门卫（UEFI）被命令“今天不检查邀请函了”（Secure Boot 被关闭），那么无论是谁都能进入，安全机制就形同虚设。
