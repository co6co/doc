# jks
`java key store`:存储密钥的`容器`。可以同时容纳n个公钥或私钥，
后缀一般是`.jks`或者`.keystore`或`.truststore`等,
使用`keytool.exe`对其进行查看，导入，导出，删除，修改密码：

可对`jks容器`加密码，输入正确才可以操作此容器中密钥。
还有一个密码的概念与上者不同，是jks中存储着的私钥的密码，通常是绝密的。

## keytool 工具
[keytool](https://www.chinassl.net/ssltools/keytool-commands.html)

```
# 生成证书
keytool -genkey -alias cc -keypass cc -keyalg RSA -keysize 1024 -validity 365 -keystore  e:/cc.keystore -storepass 123456 -dname "CN=shuany,OU=xx, O=xx, L=xx, ST=xx, C=xx";

keytool -list -v -keystore E:/cc.jks -storepass 123456	 						#可读格式
keytool -list -rfc -keystore E:/cc.jks -storepass 123456 						#编码格式输出
keytool -export -alias cc -keystore E:/cc.jks -file e:/cc.crt -storepass 123456 #导出
keytool -printcert -file e:/cc.crt												#查看导出的证书

keytool -import -alias cc1 -file e:/shuany.crt -keystore e:/cc.jks -storepass 123456 		#导入证书 别名（默认:mykey）,别名唯一)
keytool -delete -alias cc -keystore e:/cc.jks -storepass 123456								#删除证书
keytool -keypasswd -alias cc -keypass 123 -new 12345 -keystore e:/cc.jks -storepass 123456  #修改别名为 cc 的证书密码为 12345
keytool -storepasswd -keystore e:/cc.jks -storepass 123456 -new 1234567						#修改容器密码
keytool -selfcert -alias cc -keypass 12345 -keystore e:/cc.jks -storepass 123457 -dname "cn=cc,ou=cc,o=cc,c=us" #修改证书信息
keytool -selfcert -alias jj.kman.gov.cn -keypass lanbo123456 -storepass lanbo123456 -dname "cn=jj.kman.gov.cn,ou=*.jj.kman.gov.cn,o=*.jj.kman.gov.cn,c=*.jj.kman.gov.cn" -keystore  i:/cc

keytool -genkey -alias jj -keypass 123456 -keyalg RSA -keysize 1024 -validity 365 -keystore  e:/cc.jks -storepass 123456 -dname "CN=jj.kman.gov.cn,OU=xx, O=xx, L=xx, ST=xx, C=xx";




keytool -selfcert -alias mykey  -keystore e:/service.jks -storepass changeit -dname "cn=jj.kman.gov.cn,ou=cc,o=cc,c=us" #修改证书信息
```
```
::bat

@echo off

set keytool=C:\Program Files\Java\jre1.8.0_131\bin\keytool
set pw=123456
set ps=123456

set jksFile=I:\server.jks
set clientJksFile=I:\client.p12
set certFile=I:\client.cer

set host="co6co.top"

echo 生成服务器证书库..
"%keytool%" -genkey -alias server -keypass %ps% -keyalg RSA -keysize 1024 -validity 365 -keystore %jksFile% -storepass %pw% -dname "CN=%host%,OU=cc,O=cc,L=YP,ST=KM,c=cn"
echo 生成客户端证书库...
"%keytool%" -genkey -alias client -keypass %ps% -keyalg RSA -keysize 1024 -validity 365 -storetype PKCS12 -keystore %clientJksFile% -storepass %pw% -dname "CN=%host%,OU=cc,O=cc,L=YP,ST=KM,c=cn"
echo 导出客户端证书 ...
"%keytool%" -export -alias client -keystore %clientJksFile% -storetype PKCS12 -keypass  %ps% -file %certFile% -storepass %pw%

echo 客户端证书导入到服务器证书库..
"%keytool%" -import -v -file %certFile% -keystore %jksFile% -storepass %pw%
echo 服务器证书库..
"%keytool%" -list -v -keystore %jksFile% -storepass %pw%

pause

```

# 浏览器验证证书
确保您的SSL证书与`地址栏`中的`主机名称`匹配
a.主机名（在地址栏中）与证书`主题(Subject)`中的`通用名称(Common Name)`完全匹配。
b.主机名称与`通配符通用名称`相匹配。例如，www.example.com匹配通用名称* .example.com。
c.主机名 在`主题备用名称`(SAN: Subject Alternative Name)字段中列出
	- The host name (in the address bar) exactly matches the Common Name in the certificate's Subject.
	- The host name matches a Wildcard Common Name. For example, www.example.com matches the common name *.example.com.
	- The host name is listed in the Subject Alternative Name field.
	
- 是否过期
- CA是否可靠
- 返回的公钥是否能正确解开返回证书中的数字签名
- 服务器证书上的域名是否和服务器的实际域名相匹配  -- 要核对CN或SAN,见上
- 验证通过后，将继续进行通信，否则，终止通信
