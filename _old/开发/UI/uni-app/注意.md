## uni-app 使用注意
uni-app 在**发布到H5**时支持**所有vue的语法**

发布到App和小程序时 **无法实现全部vue语法**

uni-app 除了支持Vue实例的生命周期，还支持**应用生命周期**以及**页面生命周期**。
uni-app 完整支持 Vue 模板语法


`select` 标签用 `picker` 组件进行代替
`radio` 用 `radio-group` 组件进行代替

# 组件
uni-app框架中基础组件包括view、text、input、button、video等几十个基础组件

uni-app 支持`配置全局组件`，需在 main.js 里进行全局注册，注册后就可在所有页面里使用该组件
``` js
import Vue from 'vue'
    import pageHead from './components/page-head.vue'
    Vue.component('page-head',pageHead)
 ```
``` 
<template>
        <view>
            <page-head></page-head>
        </view>
    </template>
 ```

# H5 开发注意
1. H5 发布到服务器注意：配置发行后的路径（根目录可不配置），比如发行网站路径是 www.xxx.com/html5，在 `manifest.json` 文件内编辑 h5 节点，router 下增加 base 属性为 html5.
2. 引用第三方 js 的方式 在 manifest.json 文件编辑 h5 节点的 template 属性，填写 html 模版路径
3. 使用罗盘、地理位置、加速计等相关接口需要使用 https 协议
4. 组件内（页面除外）~~不支持 onLoad、onShow 等页面生命周期~~。
5. 为避免和内置组件冲突，自定义组件请加上前缀（但不能是 `u` 和 `uni`）.

# 运行原理
1. 逻辑层 
    - uni-app 在非H5端运行时，从架构上分为逻辑层和视图层两个部分。逻辑层负责执行业务逻辑，也就是运行js代码，视图层负责页面渲染。
    - 逻辑层是运行在一个独立的`jscore`里的，它不依赖于`本机的webview`，所以一方面它没有浏览器兼容问题，可以在Android4.4上跑es6代码，另一方面，它无法运行window、document、navigator、localstorage等浏览器专用的js API。

        > jscore就是一个标准js引擎，标准js是可以正常运行的
        >
        >浏览器的js引擎，就是jscore或v8的基础上新增了一批浏览器专用API，比如dom
        >
        >node.js引擎，则是v8基础上补充一些电脑专用API，比如本地io
        >
        >uni-app的App端和小程序端的js引擎，其实是在jscore上补充了一批手机端常用的JS API，比如扫码。
        >

2. 视图层

    h5和小程序平台，以及app-vue，视图层是webview。而app-nvue的视图层是基于weex改造的原生视图。
    - 在iOS上 只能使用iOS提供的webview，版本不同，表现有细微差异。
    - Android上 小程序大多自带了一个几十M的`chromium webview` ,而App不带 使用`Android system webview`（手机不同而又差异）。

3.  逻辑层和视图层分离的利与弊

    js运算不卡渲染，最简单直接的感受就是：窗体动画稳
    两层互相通信，
    Android低端机上，每次通信都要耗时几十毫秒，有几个场景表现明显：
    - 连续高帧率绘制canvas动画，会发现还不如webview内部绘制流程
    - 视图层滚动、跟手操作，不停反馈给逻辑层，js再处理逻辑并通知视图层做对应更新。此时会发现交互不跟手或卡
