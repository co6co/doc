# 1. 元编程
## 1.1 简介
java 的反射是一个比较难且主要的知识点，在很多框架都可以见到反射影子，且很多问题通过反射解决更方便；
其实java反射是元编程的一种方式；

data class 转换成map示例：
```
data class User(val name:String,val age:Int)

object User{
	fun toMap(a:User):Map<String,Any>={
		hashMapOf("name" to name,"age" to age)
	}
}
```

上面代码违背了 DRY(Don't Repeat Yourself)原则，当 data class 数量非常多的情况，
会出现结构雷同的大量的类似代码，且很容易将属性名写错。

反射实现:
```
object Mapper {
	fun <A:Any> toMap(a:A)={
		a::class.memberProperties.map{ m->
			val p=m as KProperty
			p.name to p.call(a)
			
		}.toMap()
	}
}

//使用
Mapp.toMap(new User("humora",17))
```

`a::class` 的类型是KClass，是Kotlin 中描述类型的类型（metaclass），
如果我们将User看成是描述显示概念的数据结构，那么传入的参数类型为User时，`a::class ` 为描述User类型的数据，
这样描述数据的数据就可以成为**元数据**；

## 1.2 元编程
`a::class`描述传入A的元数据，像这样操作元数据的编程可以称为元编程；
元编程就是反射这样的说法不全面。

元编程可是说：程序即是数据，数据即是程序。
前半句指的是：访问描述程序的数据，如：我们通过反射获取类型信息；
后半句则是指将这些数据转化为对应的程序，也就是所谓代码生成；

反射是获取描述程序信息的典型例子，但代码生成相对比较陌生:
```
#!/bin/sh
# metaprogram
echo '#!/bin/sh'>program
for i in $(seq 992)
do 
	echo "echo $i">>program
done

chmod +x program
```
这个例子将程序作为程序的输出，是一个非常简单的概念；
元编程就像高阶函数一样，是一种更高阶的抽象，高阶函数将函数作为输入或输出，而元编程则是将程序本身作为输入或输出；

那么元编程经过操作后能不能直接作为程序使用? 即程序即数据，数据即程序？
这个问题不同语言有不同的答案，在Kotlin中我们没办法将一个KClass修改之后将其反过来生成一个新的class来使用；
但是在Lisp中，一切都可以视为LinkedList,而Lisp的宏则允许直接将这些LinkedList作为程序的一部分。

像Lisp这样的一直性，我们称之为**同像性(homoiconicity)**.

同像性是模型编程语言的特殊属性，意味着一个程序的结构与其句法是相似的，因此易于通过阅读程序来推测程序的内在含义。
如果一门编程语言具有同像性，说明该语言的文本表示(源代码)与其抽象语法树(AST)具有相同的结构，即AST和语法同形。
该特性允许使用相同的表示语法，将语言中的所有代码当成资料来存取及转换，提供“代码即数据”的理论前提。

## 1.3 元编程技术
主流实现方式：
- 运行时通过API暴露程序信息，比如：反射机制
- 动态执行代码，多见于脚本语言，如:JavaScript 的eval函数可以动态地将文本作为代码执行；
- 通过外部程序实现目的，如编译器，在将源文件解析为AST之后，可以针对这些AST做各种转化，典型例子我们常说的语法糖，编译器会将这部分代码的AST转化为相应的等价AST，这个过程被称为desuger(解语法糖)

### 1.3.1 AST
抽象语法树，是源代码语法结构的一种抽象表示，以树状形式表现编程语言的语法结构，每个节点都代表代码中的一种结构。

之所以是抽象的，是因为这里的语法并不会表示出真是语法中出现的节点细节。

### 1.3.2 反射
KClass 是一个Kotlin的类，它的实例能作为描述其他类的元数据；像这样用Kotlin面熟Kotlin自身信息的行为就是所谓的反射或自反；

除了我们熟悉的运行时反射外，也有许多语言支持编译期反射，**编译期反射通常需要和宏等技术结合使用**，
编译器将当前程序的信息作为输入传入给宏，并将其结果作为程序的一部分；

### 1.3.3 宏
很多编译器都支持宏，但他们各自的实现却不那么相同；

C编译器有预处理的功能，支持在编译时将相应的宏调用展开成具体内容，实质就是文本替换；

诸如：Lisp和Scala这样的语言中宏更加强大，它直接在宏展开时暴漏抽象语法树，可以在宏定义中直接操作这些AST，并生成需要的AST作为程序的返回；

### 1.3.4 **模板元编程**
这可以说是C++的招牌特性，《Morden C++ Design》就是围绕着各异特性展示各种奇迹淫巧；
C++的模板元编程还具备图灵完备性，理论上可以完成所有的编程任务；


图灵完备性：如果一系列操作数据的规则（如指令集、编程语言、细胞自动机）可以用来模拟单带图灵机，那么它是图灵完备的。
## 1.3.5 路径依赖类型
支持路径依赖的语言通过可以在编译时从类型层面避免大部分bug。
由于这个特性通常只在一些学术型编程语言 如：Haskell、Scala中出现，实践中应用不广泛。

- KClass和Java 的Class 可以看作同一含义的类型，并且可以通过.java和.kotlin 方法在KClass和Class直接相互转化。

Kotlin的反射和java比较相近，当碰到一些Kotlin独有的特性时，Kotlin编译器会在生产的字节码中存储额外的
信息，这些信息通过kotlin.Metadata注解实现，Kotlin编译器会将Metadata标注的这些类。
Kotlin的Lambda没有采用invokeDynamic指令实现，这可能也是一个很大的原因。
要实现将现有Metadata机制自适应新的invokeDynmic指令，有巨大的工作量和兼容性问题。

# 3. Kotlin注解
kotlin.Metadata 这是实现Kotlin大部分独特特性反射的关键，Kotlin将这些信息直接以注解形式存储在字节码文件中，以便运行时反射可以获取这些数据；

Kotlin兼容java所有Java可以增加注解的地方，Kotlin也可以，Kotlin简化了注解创建语法：
```
anotation class FooAnnotation(val bar:String)
```
和java 一样注解参数只能是常量，支持类型：
- 与Java对应的基本类型
- 字符串
- Class对象（Kclass 或者 java的Class）
- 其他注解
- 上述类型数组，基本类型数组需要指定对应的XXXArray，如 IntArray，而不是Array<Int>

注解的位置：
- Documented 文档（通过是API文档）中必须出现该注解
- Inherited 如果超类标注了该类型，其子类也将字段标注该注解而需指定
- Repeatable 注解在同一位置可以出现多次
- Retention 表示注解用途，有3种取值；
- Sourc 仅在源代码种存在，编译后Class文件种不包含该注解信息；
- CLASS class文件种存在该注解，但不能被反射读取；
- RUNTIM 注解保存在class种且可以在运行时通过反射获取
- Target 注解应用位置

Kotlin目前不支持Inherited ;

## 3.1 精确控制注解位置
```
@Cache(namespace="hero",expires=3600)
data class Hero(
	@property:CacheKey(keyName="heroName",buckets=indexOf(1,2.3))
	val name:string
	
	@field:CacheKey(keyName="atk",buckets=indexOf(1,2.3))
	val attack:Int
	
	@get:CacheKey(keyName="def",buckets=indexOf(1,2.3))
	val defense:Int
	
	val initHp:Int
)
```

注解本身也是代码的一部分，Kotlin提供以下方法获取注解信息：

- 反射
```
val cacheAnnotion=Hero::class.anotation.find{it is Cache} as Cache?
println("namespace ${cacheAnnotion?.namespace}")
println("expires ${cacheAnnotion?.expires}")
```

- 注解处理器
 JSR269 引入了注解处理器(annotation processors),允许无名在编译过程种挂钩子实现代码生成；
 通过此dagger之类的框架实现了编译时依赖注入这样需要通过运行时反射支持的特性
