# 1. 函数式编程
狭义：有着非常简单且严格的语言标准，即只通过纯函数进行编程，不允许有副作用；Haskell所代表的纯函数式语言；
广义：任何“以函数为中心进行的编程”的语言都可以称为函数式编程；并不强调函数是否都是“纯”的；

常见特性：
- 函数是一等公民；
- 方便的闭包语法
- 递归式构造列表
- 柯里化的函数
- 惰性求值
- 模式匹配
- 尾递归优化	

如果支持静态类型的函数式语言 可能还支持:
- Typeclass
- 类型推导

Kotlin 支持以上代表性的函数式语言列表的绝大对数，因此它可以被称为广义上的函数式语言；


## 1.1 引用透明性
纯函数十分接近数学中的函数，它的评判标准也源于数学中的一个级别原则， 即需要具备引用透明性；

引用透明性：简单理解为：一个表达式在程序中可以被它等价的值替换而不影响结果；
## 1.2 局限性
绝大多数场景都利用纯函数的设计，但也有不能胜任的时候，随机函数（不是纯函数），每次输出的随机数都不相同；

##1.3 应用序与正则序
```
//符合引用透明性的代码
fun f1(x:Int,y:Int)=x
fun f2(x:Int)=f2(x)

//执行
f1(1,f2(2))
```
执行它 f2必然被不断调用，从而导致 `eval to bottom` 产生死循环

纯函数所谓“相同的计算结果” 还可以是死循环；

Haskell 程序员将其翻译为：
```
//  * == x
f1::Int->Int->Int
f1 * y =x+y
f2::Int->Int
f2 *= x
```
 
奇怪的是结果返回1；

### 1.3.1 求值策略
编程语言表达式求值策略: 编程语言中存两种不同的代换模型:应用序和正则序；
大部分语言 Kotlin、C、Java是 “应用序”语言，当要执行一个过程时，就会对过程参数进行求值，这也就是上述Kotlin代码导致死循环的原因：
当我们调用 `f1(1,f2(2))`的时候，程序会对`f2(2)`进行求值，从而不断调用f2函数；
而Hashkell采用不一样的逻辑：它会延迟对过程参数的求值，直到确实需要到它的时候，才进行计算，这就是所谓的“正则序”，
正则序是一个惰性求值的过程；

### 1.3.2 惰性求值
Haskell 默认采用惰性求值，在Kotlin和其他一些语言(Scala、Swift),可以利用 **lazy**关键字声明惰性的变量和函数；
惰性求值可以带来很多优势，如无限长的列表结构，当然也会制造一些麻烦，比如它会让程序求值模型变得更加复杂，滥用会导致效率下降；

在Haskell中惰性求值主要靠Thunk这种机制来实现，

## 1.4 高阶类型简述
函数式编程是一种更加抽象的编程思维方式，将业务进行高度抽象为业务对象，然后进行组合；

java 中经常会接触到一阶的参数多态，这也是我们熟悉的泛型，利用泛型多态可以很大程度的减少相同的代码，
然而我们需要更高阶的抽象的时候，泛型也避免不了代码冗余。
比如标准库中的List、Set等都实现了Iterable接口，他们都有相同的方法(filter、remove 等)。

尝试用泛型设计Iterable：
```
interfave iterable<T>{
	fun filter(p:(T)->Boolean):Iterable<T>
	fun remove(p:(T)->Boolean):Iterable<T>=filter{x->!p(x)} 
}
```
当我们用List取实现Iterable时，由于 方法需要返回具体的容器类型，需要重新实现这些方法：
```
interfave List<T> :Iterable<T>{
	fun filter(p:(T)->Boolean):List<T>
	fun remove(p:(T)->Boolean):List<T>=filter{x->!p(x)} 
}
```
相同的道理其他容器类也需要类似的实现；

这种利用一阶参数多态的技术依旧存在代码冗余，现在假设类型也能像数学中的函数一样支持高阶，即可以通过类型来创建新的类型，
那么多阶类型就可以上升到更高的抽象，从而进一步消除冗余的代码。

## 1.5 高阶类型： 用类型构造新类型
类型构造器(Type constructor),比较熟悉的是 值构造器(Value constructor),
很多情况，值构造器可以是一个函数，我们可以给一个函数传递一个值参数，从而构造出一个新的值：
```
(x:Int)->x
```
如果是类型构造器，就可以传递一个类型变量，然后构造出一个新的类型，比如List[T],当我们传入Int时，就可以构造出List[Int]类型；
上面所述，值构造函数的返回结果x是具体的值，List[T]传入类型变量后，也是具体的类型，

当我们讨论‘一阶’概念时，具体的值或信息就是构造的结果。
- 一阶值构造器：通过传入一个具体的值，然后构造出另一个具体的值；
- 一阶类型构造器：通过传入一个具体的类型变量，然而构造出另一个具体的类型；

在理解上述概念后，高阶函数就更好理解，它突破了一阶构造器，可以支持传入一个值构造器，返回另一个值构造器；
```
{x:(Int)->Int->x(1)}
{x:Int->{y:Int->x+y}}
```
类似地，高阶类型可以支持传入构造器变量，可以构造出另一个类型构造器；
**假设Kotlin支持高阶类型的语法**，我们可以定义一种类型构造器Container，然后将其作为另一个类型构造器Interable的类型变量：
```
interface Iterable<T,Container<T>>{
	fun filter(p:(T)->Boolean):Container<T>
	fun remove(p:(T)->Boolean):Container<T>=filter{x->!p(x)} 
}
```
之后，我们再利用这种特性重新实现List 等集合，这时会发现冗余的代码消失了：
```
interface List<T>:Iterable<T,List>
interface Set<T>:Iterable<T,Set>
```

# 2. 高阶类型 与Typeclass
在Haskell中高阶类型的特性天然催生了这门语言中的一个非常强大的语言特性---Typeclass。
我们将利用Kotlin 扩展语法，来代替高阶类型实现这一特性；

## 2.1 函子
先用Scala语言，实现一个常见的Typeclass，Functor(函子)，继而理解什么是Typeclass

**函子**: 高阶类型之间的映射；

**函数式编程非常近似数学，或者说，函数式编程思想的背后理论是一套被叫做范畴理论的学科；**

范畴论是抽象地处理数学结构以及结构之间联系的一门数学理论，以抽象的方法来处理数学概念将这些概念形成一组组“物件”及“态射”。

在编程中，函数其实就可以看成具体类型之间的映射关系；函子可以看成高阶类型的参数类型之间的映射；

使用Scala定义一个高阶类型Functor
```
trait Functor[F[_]]{
	def fmap[A,B](fa:F[A],f:A=>B):F[B]
}
```
- trait 近似于 interface, 因为它支持高阶类型，所有支持传入类型变量F
- Functor中实现了一个fmap方法，它接收一个类型为F[A]的参数，以及一个函数fa，把fa中的元素类型A映射成B

希望List[Int] 转化为字符串，List[T] 集成Functor的功能
```
implicit val listFunctor=new Functor[List]{
	def fmap (fa:List[A])(f:A=>B)=fa.map(f) 
}
```

## 2.2 扩展方法实现Typeclass
Kotlin 并不支持高阶类型，论文《Lighweight higher-kinded polymorphism》 中阐述了一种模拟高阶类型的方法；
```

interface Kind<out F,out A>

interface Functor<T>{
	fun <A,B> Kind<F,A>.map(f:(A-B):Kind<F,B>
}
```

应用到类型List中
```
sealed class List<out A> :Kind<List.K,A>{
	object K
}
object Nil:List<Nothine>{}
data class Cons<T>(val head:A,val tail:List<A>):List<A>{}
```
list由两个状态构成，一个Nil代表空列表，里一个Cons便是由head和tail连接而成的列表；

- List实现了`Kind<List.K,A>`,代入上面Kind的定义，得到`List<A >`是类型构造器List.K 应用类型参数A 之后得到的类型。
由此我们可以用List.Kind代表List这个高阶类型。

List的Functor实例：
```
@Suppress("UNCHECKED_CAST","NOTHING_TO_INLINE")
inline fun <A> Kind<List.K,A>.upwrap():List<A>= 
	this as List<A> object ListFunctor:Functor<Listt.k>{
		overribe fun <A,B> Kind<List.K,A>.map(f:(A)-B):Kind<List,K,B>{
			return when (this){
				is Cons->{
					val t =this.tail.map(f).unwrap()
					Cons<B>(f(this.head),t)
				}
				else ->Nil
			}
		}
	}
```

Kotlin 无法将Object内部的扩展方法直接导入进来，即下面代码不被允许：
```
import ListFunctor.*
Cons(1,Nil).map{it+1}

```
我们没法直接导入定义在object里的扩展方法，Kotlin中receiver机制可以将object中的成员引入作用域，所有，我们只需要用run函数，就可以使用这个实例：
```
ListFunctor.run{
	Cons(1,Nil).map{it+1}
}
```

### 2.2.1  Typeclass 设计常用功能
上面是Kotlin模拟实现Typeclass，总结具体做法：
a. 利用类型的扩展语法定义通用的Typeclass接口；
b. 通过object定义具体类型的Typeclass实例；
c. 在实例run函数的闭包中，目标类型的对象或值随之支持了相应的typeclass的功能；

#### 2.2.1.1. Eq设计
为一种类型定义一个Eq的Typeclass实例，就可以在实例如你函数中对该类型的对象或值进行判断等操作；
根据上面总结定义EQ：
 
```
//步骤a
interface Eq<F>{
	fun F.eq(that:F):Boolean
}
//步骤b
//常见的Int为例
object IntEq:Eq<Int>{
	overribe  fun Int.eq(that:Int):Boolean{
		return this==that
	}
}
//步骤c
IntEq.run{
	val a=1
	print(a.wq(1))
	print(a.wq(2))
}
```

让Eq来支持高阶类型：
Functor中 自定义了一个List类型，同样以 `Kind<List.K,A>`为例，来实现ListEq的Typeclass

//步骤a
```
abstract class ListEq<A>(val a:Eq<A>):Eq<Kind<List.K,A>>{
	overribe fun Kind<Kist.K,A>.eq(that:Kind<List.K,A>):Boolean{
		val curr=this
		return if(curr is Cons &&that is Cons){
			val headEq=a.run{
				curr.head.eq(that.head)
			}
			if(headEq) curr.tail.eq(that.tail) else false
		} else if (curr is Nill && that is Nil){
			true
		} else false
	}
}
```

ListEq 是一个抽象类，接收一个类型为Eq 的实例,由于要模拟支持高阶类型的效果，ListEq 又实现了`Eq<Kind<List.K,A>`，
当为`Kind<List.K,A>`类型扩展wq方法的时候，我们就可以在它的内部实现中调用a.eq方法；

```
//步骤b
object IntListEq:ListEq<Int>(IntEq)
//步骤c
ListListEq.run{
	val a=Cons(1,Cons(2,Nil))
	println(a.eq(Cons(1,Cons(2,Nil))))
	println(a.eq( Cons(2,Nil)))
}
```
#### 2.2.1.1. Show 和Foldable
java中某个类实现toString的方法，现在我们通过设计一个叫Show的TypeClass来实现类似的功能；
```
interface Show<F>{
	fun F.show():String
}

//假设现有一个类Book，
class Book(val name:String)

object BookShow:Show<Book>{
	overribe fun Book.show():String=this.name
}
//测试
BookShow.run{
	println(Book("Kotlin").show())
}
```

为List类型增加Show的操作，与Eq不同，List的打印结果需要将元素的打印结果都拼装起来，即我们需要对List类增加一个类似于fold的操作；
因此实现Show之前，我们设计另外一个支持高阶类型想过的Foldable：
```
interface Foldable<F>{
	fun <A,B> Kind<F,A>.fold<init:B):((B,A)-B)->B
}
@Suppress("UNCHECKED_CAST","NOTHING_TO_INLINE")
inline fun <A> Kind<List.K,A>.unwrap():List<A>=
	this as List<A> object ListFoldable:Foldable<List.K>{
		overribe fun <A,B>Kind<List.K,A>.fold(init :B):((B,A)->B)={
			f-> fun fold0(l:List<A>,v:B):B{
				return when (l){
					is Cons->{
						fold0(l.tail,f(v,head))
					}
					else ->v
				}
			}
			fold0(this.unwrap(),init)
		}
		
	}
```

Foldable 为·`Kind<List.K,A>`类型扩展了fold操作，有了它后就可以实现Listshow了，
```
abstract class ListShow<A>(val a:Show<A>):Show<Kind<List.K,A>>{
	overribe fun Kind<List.K,A>.show():String{
		val fa=this
		return "["+ListFoldable.run{
			fa.fold(listOf<String>())({r,i-> 
				r+r.run{i.show()}
				}).joinToString()+"]"
		}
	}
}

object BookListShow:ListShow<Book>(BookShow)

BookListShow.run{
		println(
			Cons(
				Book("K"),
				Cons(Book("Kotlin"),Nil) 
		).show()
	)
}
```

Kotlin 中模拟Typeclass，感觉方法繁琐，Typeclass 这种多态技术十分适合函数式编程，例如我们实现Show的适合，
引入了里一个Foldable，typeclass之间的组合使得用他们进行程序设计非常灵活且低耦合；

## 2.3 Monoid
Monoid一方面其实是一个很简单的Tpeclass，另一方面，也被用来描述某种代数，这类代数遵循Monoid法则，即集合律和同一律；

一个Monoid由几部分组成：
a. 一个抽象类A
b. 一个满足集合律的二元操作 append，接收任意两个A类型的参数，返回一个A类型的结果；
c. 一个单位元zero，它同样也是A类型的一个值；
d. 集合律 append(a,append(b,c)) == append(append(a,b),c),这个等式对任何A类型的值(a,b,c)均成立；
e.同一律 append(a,zero)==a 或者append(zero,a)==a.

利用Kotlin表达Monoid这个数据类型(新的Typeclass)
```
interface Monoid<A>{
	fun zero():A
	fun A.append(b:A):A
}
```
拼接字符串是一个典型的符合Monoid法则的具体例子；
```
object stringConcatMonoid:Monoid<String>{
	override fun String.append(b:Sring):String=this+b
	overribe fun zero():String=""
}
```

Monoid 是一种通用的数据结构，意味着我们可以利用它来编写通用代码；

其定义非常简单，然它于列表结构联系在一起，可以发挥很大的作用；
假如我们相对前面定义的list扩展一个sum方法：
```
fun <A> List<A>.sum(ma:Monoid<A>):A{
	val fa=this
	return ListFodable.run{
		fa.fold(ma.zero())({
			s,i-> ma.run{
				a.append(i)
			}
		})
	}
}
```
sum方法接收一个Monoid<A>类型的参数ma
Monoid这种抽象结构非常适合fold这种折叠操作；
回顾fold相关方法的定义：
```
inline fun <T,R> iterable<T>.fold(
	initial:R
	operation:(acc:R,T)->R
):R
```
fold 接收两个参数 initial 和operation 恰好对应了Monoid<A> 中的zero单位元和append操作；

```
println(
	Cons(
		"Dive",
		Cons("Into",Cons("Kotlin",Nill))
	).sum(stringConcatMonoid)
)
```

## 2.4 monoad 幺半群
回味下monoid 当我们用Monoid<A>、Monoid<B> 组合出一个新的Monoid<C>,新的Monoid依旧遵循Monoid法则；
我们只要遵循数学定理一样进行组合，就无需关注具体的类型（A、B）细节，最终推到出来的结果依旧正确；

Monad 幺半群
Monad也是函数式编程范式中最通用的结构，利用它可以运用组合思想来抽象绝大部分事物；
Monad 一个有名的解读（Phillip Wadler）：Monad无非就是个自函子范畴上的幺半群

**函子定律** 

函子也是一种通用的抽象数据结构，它为类型Kind<F,A>定义了map操作，返回另一个类型Kind<F,B>:
```
interface Kind<out F,out A>
interface Functor<F>{
	fun <A,B> Kind<F,A>map(f:(A)->B):Kind<F,B>
}
```
类型参数F模拟了高阶类型中的类型构造器；
前面例子中，我们用List.K 来替代F，代表这是一个列表容器；
实际上，我们的F还可以是其他类型的构造器：
- `Kind<Option.K,A>`代表可空或存在的高阶类型； 
- `Kind<Effect.K,A>`代表拥有副作用的高阶类型
- `Kind<Parser.K,A>`代表解析器的高阶类型

尽管这些构造器虽然容器不同，并且容器内的值只要一个，如Option.K 容器内只存在两种可能的取值(空或存在的值)，
然而它们都可以看成阉割版的List.K, 并且都可以用来派生出Functor的具体Typeclass实例
```
object OptionFunctor:Functor<Option.K>{
	overribe def fun <A,B>Kind<Option.K,A>.map(f:(A)->B):Kind<Option.K,B>{
		....
	}
}
...

```
这些Functor的实例都遵循函子定律
- 同一律法则；
- 用map进行组合满足结合律

函子定律包装了实例本身的容器F不变，但我们可以改变容器内部的程序状态，主要通过map方法来实现
并且map适用的函数进行组合；
然而 Functor的作用比较有限，函数式编程思想是站在更高的层次去抽象业务，然后进行组合；
显然Functor的map操作并没有为我们提供足够高的抽象组合能力；

如果我们将高阶类型 Kind<F,A> 比作一个管道，Functor提供了一种能力，支持对管道内的状态进行转化操作，简化为一个map操作；
```
fun <F,A>map(fa:Kind<F,A>,f:(A)->B):Kind<F,B>

``` 
拥有相同容器类型F的管道其实规格相同，表明他们容易被组合，因此我们需要有个新的map2 函数来支持操作:
```
fun <A,B,C> map2(fa:Kind<F,A>,fb:Kind<F,B>,f:(A,B)->C):Kind<F,C>
```
有了map2 ，会发现整个抽象层次更高了，与纯map操作不同，充满了副作用，它们无法在业务中被避免，然而，假使我们将副作用限制在管道容器内，并将管道视为一个拥有原则性的整体，就这个层面而言，它依旧是引用透明性的，
于是我们将相同容器的副作用操作利用函数f进行组合，尽量推迟到最后执行，这就是典型的函数式编程；

## 2.4.2 flatMap
如何为高阶类型实现map2的效果，先直接利用map，我们可能得到一个嵌套容器的结构：
`Kind<F,A> `进行map，返回一个`Kind<F,B>`的函数，那么得到的结构将是`Kind<F,Kind<F,B>>`,我们需要一个flatten的操作，才能得到Kind<F,B>

Kotlin中的flatMap支持flatten操作；本质上可以看成map与flatten的结合操作；
因此要实现map2函数效果，一种思路是 给高级类型也扩展一个flatMap方法：
```
fun <A,B> Kind<F,A>.flatMap(f:(A)->Kind<F,B>):Kind<F,B>
```

有了flatMap方法，我们就很容易实现map2函数：
```
fun <A,B,C> map2(fa:Kind<F,A>,fb:Kind<F,B>,f:(A,B)->C) :Kind<F,C>{
	fa.flatMap{f->fb.map(b->f(a,b)}
}
```
我们利用高阶类型进行函数编程时，flatMap是一个至关重要的方法，
更有趣的是：如果我们再引入一个pure 方法，那么map方法同样也可以用flatmap来实现；

pure有时候也被叫做unit，他核心作用就是将一个A类型的参数，转化为Kind<F,A>类型；
```
fun <A> pure(a:A):Kind<F,A>
```

下面如何利用unit和flatMap方法来定义map
```
fun <A,B>map (fa:Kind<F,A>,f:(A)->B):Kind<F,B>={
	flatMap(fa){a->pure(f(a))}
}
```

因此 pure和flatMap可以作为一种最小的原始操作集合，利用这两个函数组合我们可以实现map、map2及更加复杂的数据转化操作；
那么我们再定义一种新的Typeclass，同时包含了pure和flatMap操作，
那么它将是一种最通用的函数式结构 这就是Monad；

## 2.5 Monad
我们需要对Monad Typeclass及Monad概念本身进行区分，准确地说 ，Monad是满足Monad法则的一个最小集的实现，
它可被称为单子，然而这个实现的组合并不是唯一的， 
比如我们可以利用pure和flatMap来满足这个法则，同时也可以利用pure、compose来代替实现；

因此我们定义一个名为Monad<F>的Typeclass，只是其中一个版本，然而它满足Monad法则；
```
interface Monad<F>{
	fun <A> pure(a:A):Kind<F,A>
	fun <A,B> Kind<F,A>.flatMap(f:(A)->Kind<F,B>):Kind<F,B>
}
```

我们为Monad<F> 定义了pure方法，以及利用Kotlin语言特性，为模拟的高阶类型Kind<F,A>扩展了flatMap方法，
在用Monad<F>之后，我们先用它来创建ListMonad实例：
```
object ListMonad:Monad<List.K>{
	private fun <A> append(fa:Kind<List.K,A>,fb:Kind<List.K,A>):Kind<List.K,A>{
		return if(fa is Cons){
			Cons(fa.head,append(fa.tail,fb).unwrap())
		}else {
			fb
		}
	}
	overribe fun <A> pure(a:A):Kind<List.K,A>{
		return Cons(a,Nil)
	}
	overribe fun <A,B> Kind<List.K,A).flatMap(f:(A)->Kind<List.K,B>):Kind<List.K,B>{
		val fa=this
		val empty:Kind<List.K,B>=Nil
		return ListFodable.run{
			fa.fold(empty)({r,l->append(r,f(l))})
		}
	}
}

```

Applicative 重新定义Monad
用pure和flatMap可以实现map，所有Monad其实都可以是Functor，那么我们是否可以在定义Monad<F>的时候直接实现Functor<F>

```
interface Monad<F>:Functor<F>{}
```
这样我们给所有的Monad<F>操作扩展了map操作，事实上，数学中的3种代数结构存在如下以来关系：
```
Functor->Applicative->Monad
```
也就是说Monad都是Applicative，所有的Applicative都是Functor

 ```
 interface Applicative<F>:Functor<F>{
	fun <A> pure(a:A):Kind<F,A>
	fun <A,B> Kind<F,A>.ap(f:Kind<F,(A)->B>):Kind<F,B>
	overribe fun <A,B> Kind<F,A>.map<f:(A)->B):Kind<F,B>{
		return ap(pure(f))
	}
 }
 ```
 
 有了Applicative 我们重新定义Monad
 ```
 interface Monad<F> :Applicative<F>{
	fun <A,B> Kind<F,A>.flatMap<f:(A)->Kind<F,B>):Kind<F,B>
	overribe fun <A,B> Kind<F,A>.ap(f:Kind<F,(A)->B>):Kind<F,B>{
		return f.flatMap{
			fn->this.flatMap{a->pure(fn(a))}
		}
	}
 }
 ```

 ```
 object OptionMonad:Monad<Option.K>{
	overribe fun <A,B> Kind<Option.K,A>.flatMap(f:(A)->Kind<Option.K,B>){
		val oa=this
		return when(oa){
			is Some->f(oa.value)
			else ->None
		}
	}
	overribe fun <A> pure(a:A):Kind<Option.K,A>{
		return Some(a)
	}
 }

 fun readInt():StdIO<Option<Int>>{
	return StdIOMonad.run{
		val r=StdIO.read().map{
			when{
				it.matches(Regex("[0-9]"))->Some(it.toInt())
				else ->None
			} 
		}
		r.unwrap()
	}

 fun addOption(oa:Option<Int>,ob:Option<Int>)={
	OptionMonad.run{
		oa.flatMap{
			a->ob.map{b->a+b}
		}
	}
 }
 ```
