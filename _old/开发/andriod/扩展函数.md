# 1. Kotlin 扩展特性
## 1.1 扩展函数
扩展函数的关键字是`<Type>`,此外我们需要一个`接收者类型(recievier type)`(通常是类或接口名称)来作为他的前缀。
```
fun MutableList<Int>.exchange(fromIndex.Int,toIndex:Int){
	val tmp=this[formIndex]
	this[formIndex]=this[toIndex]
	this[toIndex]=tmp
}
```
Kotlin的this要比Java更灵活，在扩展函数体里this代码的是**接收者类型的对象**

注意：Kotlin严格区分接收者是否可空，如果可空，需要重新一个可空类型的扩展函数。


```
fun Any?.toString(): String {
	////可空的接收者类型定义扩展。这样的扩展可以在对象变量上调用， 即使其值为 null
    if (this == null) return "null"
    // 空检测之后，“this”会自动转换为非空类型，所以下面的 toString()
    // 解析为 Any 类的成员函数
    return toString()
}
```

可将扩展函数近似理解为静态方法，它独立于该类的任何对象，且不依赖类的实例，
该类的所有实例共享，被public修饰的静态方法本质上也是全局方法；

扩展函数不会端来额外的性能销毁；

### 1.1.2 作用域
一般来说我们习惯将扩展函数定义在函数包内，在同一个包内可以直接调用 扩展方法（exchange），如果其他包要调用，
只需import相应的方法即可。

实际开发中，我们可能会将扩展函数定义在一个Class内部统一管理：
```
class Extends{
	fun MutableList<Int>.exchange(...){
		...
	}
}
```
与以前的调用方式不能调用，借助IDEA可以查看对应的源码：
```
public static final class Extends{
	public final void exchange(@NotNull List $receiver,int formIndex,int toIndex){
		intrinsics.checkParameterIsNotNull($receiver,"$receiver");
		int tmp=...
		...
	}
}
```
exchange 方法没有**static**关键字修饰，
所有当扩展函数(public 修饰)在一个Class内部时，我们只能在该类或其子类中调用；

## 1.2 扩展属性
与扩展类类型 ，可以为一个类增加扩展属性，
如果我们想为Mutable<Int>增加一个判断是否为偶数的属性：

```
val MutableList<Int>.sumIsEven:Boolean
	get()=this.sum()%2==0

```

定义扩展函数的默认值：
```
//编译出错，扩展属性不能有初始化
val MutableList<Int>.sumIsEven:Boolean=false
```
与扩展函数一样，其本质也是对应java中的静态方法，
**由于扩展没有实际将成员插入类中**，因此对扩展属性来说幕后字段无效的，我们只能显示提供 setters和getters定义；

**幕后字段**:如果属性存在访问器使用默认实现，那么Kotlin会自动提供幕后自动filed;

# 2. 扩展的特殊情况（局限）
## 2.1 没有伴生类的麻烦

如果需要声明一个静态的扩展函数，开发者必须将接收器定义在伴生对象（companion object）上，
类如果已经有伴生对象，且不想在类上定义扩展函数，而是在Companion上定义扩展函数：
```
fun Son.Companion.foo(){
	...
}
```
这样，能在Son没有实例对象的情况下，也能调用扩展函数；

当我们想让第三方库也支持这样的写法，发现并不是所有的第三方库中的类都有companion对象，
只能通过实例来进行调用，这样会造成很多不必要的麻烦；

## 2.2 成员函数优先级高于扩展函数；
当现有成员方法和扩展函数同时存在，Kotlin将会默认使用类的成员方法；

## 2.3 类实例与接收者实例
当在扩展函数里调用this时，指代的是接收者类型的实例，
如果在这里扩展函数声明在一个object内部，我们如何通过this获取类的实例：
```
class Son{
	fun foo(){
		println("foo in Class Son")
	}
}

object Parent{
	fun foo(){
		println("foo in Class Parent")
	} 
	@JvmStatic
	fun main(){
		fun Son.foo2(){
			this.foo()
			//类实例 
			this@Parent.foo()
		}
		Son().foo2()
	}
}
```

`this@类名`  强行指定调用的this, 
如果 Son 的扩展函数在Paren里面 `this@Parent.foo()` 将无法调用，如下面代码：
	
```
	object Parent{
		fun foo(){
			println("foo in Class Parent")
		}
		/* Son 的扩展函数在Paren里面 
		 */
		fun Son.foo2(){
			this.foo()
			this@Parent.foo()
		} 
	}

	object Test{
		@JvmStatic
		fun main(){ 
			Son().foo2() //无法访问
		} 
	}

   //通过字节码获得的代码
	public final class Parent{
		public final void foo(){
			...
		}
		//Son 的扩展函数在Paren里面
		public final void foot2(@NotNull Son $receiver){
			Intrinsics.checkParameterIsNotNull($receiver,"")
			$.receiver.foo();
			this.foo();
		}
	}
```
	
在类中的(public)扩展函数只能在该类/子类中访问

# 3. 标准库中的函数
## 3.1 run 
`public inline run<R,R> T.run(block:T.()->R):R=block()`,

在run函数中我们拥有一个单独的作用域，能够重新定义一个变量，且它的作用域只存在run函数中；
```
fun testFoo(){
 val nickName="Prefert"
 run{
	val nickName="YarenTang"
	println(nickName)
	//返回范围内最后一个对象
 }
 println(nickName) //Prefert
}
```

## 3.2. let
`pbulic inline fun <T,R> T.let(block:(T)->R):R=block(this)`
let 和apply类型，唯一不同的时返回值:
- applay 返回的是原来的对象
- let 返回闭包里面的最后一行的值；

与run一样，同样限制了变量的作用域；

## 3.3 also
kotlin 1.1 版本中新增内容，它像是let和applay函数的加强版； 需要区分 apply 里面的this
提供给开发者，在lambde中访问上下文、接收对象，返回接收对象的使用方式：

`public inlin fun <T> T.also(block:(T)->Unit):T{block(this);return this}`

```
class Kot{
	var age=0
	fun dealStu(){
		val result=student?.also{ stu->  //隐式参数it 指定为stu，可以不用转换
			this.age+=stu.age
			this.age
		}
	}
} 
```

如果student 不为空，发现返回student且Kot的年龄也增加了,返回对象是student； 
如果使用apply 由于它内部是一个扩展函数，
this将指向 stu而不是Kot，此处我们无法调用Kot下的age

总结:
- apply: 只能使用接收类型的对象(使用this访问)，返回 接收类型对象；
- let：  使用接收接收类型的对象(it)和let所在上下文(this),返回最后一行；
- also:  使用接收接收类型的对象(it)和also所在上下文(this),返回接收类型对象

## 3.4 takeif
如果我们不仅仅只想判空，还想加入条件，let可能显得有点不足，Kotlin1.1 新增takeif，当接收器满足某些条件时它才会执行：
```
//定义
public inline fun<T> t.takeif(predicate:(T)->Boolean):T?=return if (predicate(this)) this else null
 
val result student.takeif{if.age>=18}.let{...}
```

这与集合中`filter`类似，不过takeif只操作单条数据，
与`takeif`相反的 `takeUnless`，即不满足特点条件才会执行；

# 4 扩展不是万能的；
Kotlin是一种静态类型语言，我们创建的每个对象不仅具有运行时，还具有编译时类型；
在使用扩展函数时，要清楚静态和动态间的区别；

- 重写(Override)
```
class base{
	public void fun(){
		//base
	}
}
class Extended extends base{
	@override
	public void fun(){
		//Extended
	}
}

Base base=new Extended();
base.fun();
```
 
base变量具有编译时类型Base和运行时类型Extended，调用 foo()将使用运行时类型方法；
 
- 重载方法
重载时，调用变为静态，且取决于编译时类型；
 ```
 void foo(Base base){}
 void foo(Extended extended){}
 
 publicstatic main(){
	Base base=new Extended();
	foo(base)
 }
 ```

**即使base本质上是Extended的实例，最终还是会执行Base的方法**
