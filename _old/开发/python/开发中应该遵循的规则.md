# 模块开发中的意见
1. 在Python 中你总是位于某个模块内，即使在交互式命令行下输入代码实际上也存于一个名为`__main__`的内置模块中。
2. 最小化模块耦合，除了主动导入的函数和类外，模块应该尽可能独立于其他模块内使用的全局变量
3. 模块应尽可能不去更改其他模块的变量。
4. 模块中的数据隐藏，是一种惯例，而不是一种语法约束。
```
unders.py
	a,_b,c,_d=1,2,3,4

>>> from unders import *
>>> _b 
NameError:name '_b' is not defined

>>> import unders
>>> unders._b
2


```
可能把变量名的字符串列表赋值给变量 `__all__`,从而实现类似于`_X`的命名惯例的隐藏想过；
使用 `from *` 语句，只会把列在 `__all__` 列表的这些名称复制出来(包括那些那些一`_`开头的变量)
```
# all.py
	__all__=['a','_c']
	a,b,_c,_d=1,2,3,4
	
>> from alls import *
>> a,_c
(1,3)
>> b
NameError:name 'b' is no defined

>> from alls import a,b,_c,_d
>>a,b,_c,_d
(1,2,3,4)
```

5. 启用未来语言特性
```
from __future__ import featurename # 文件第一行可执行语句【可能影响 Python2.x中现存的程序代码，作为可选扩展】

```

6. 模块名
每个模块都有一个名为 `__name__` 的内置对象
遵循下面规则自动创建及赋值：
- 如果文件作为顶层程序文件执行，在启动时 __name__ 被赋值为 `__main__`
- 如果文件被导入，__name__ 就会改设诶个客户程序所了解的模块名。

7. 用名称字符串导入模块
模块名是被`硬编码的变量名`,有时程序可以运作以字符串的形式获取要导入的模块名；
但在GUI中设置时，无法导入，因为Python在import中需要一个`字面量`形式的变量,
而非是计算出来的变量名称；

```
x='string'
import x # python 将尝试导入x.py 的文件

>>modname='string'
>>exec("import "+ modname) # exec 会编译一个代码字符串，并把它传给Python 解释器执行；
						   # 字节码编译器在运行时可用，因此可用构建运行其他程序；
						   # 默认情况下 exec会在当前作用域中运行代码[可传入可选的命名空间字典指定其他特定的作用域]
						   
						   # 缺点：安全问题
						   #       每次运行必须编译import语句，编译过程可能很慢
>>string

# 可以使用copile内置工具将其预编译为字节码来提速；
>>modname='string'
>>string= __import___(modname)
```
