# Windows Server 2008 TCP 端口释放指南

在 Windows Server 2008 中，TCP 端口的释放由操作系统内核自动管理。然而，在长时间运行或特定条件下，比如服务器运行时间过长（超过 497 天），
可能会出现端口未及时释放的情况。
以下是一些解决 TCP 端口释放问题的策略：

## 1. 理解 TIME_WAIT 状态

- **TIME_WAIT**：当一个 TCP 连接被关闭后，它会进入 TIME_WAIT 状态，以确保所有数据包在网络中消失，防止旧的连接数据包干扰新连接。默认状态下，TIME_WAIT 状态将持续大约 2MSL（两倍的报文段生存时间）。

## 2. 常规解决方案

### 2.1 等待 TIME_WAIT 超时

- **等待**：有时，仅仅等待 TIME_WAIT 状态的超时周期结束，端口便会自动释放。

### 2.2 调整 TCP 参数

你可以尝试调整系统内核参数来减少`TIME_WAIT`状态的持续时间或增加端口池大小。例如，可以修改注册表中的以下键值：

1. **TcpTimedWaitDelay**：控制`TIME_WAIT`状态的持续时间，通常为 120 秒。你可能需要将其设置为一个较小的值（如 30 秒），但要小心，因为太小的值可能会导致数据包丢失。

   路径: `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`

2. **TcpMaxPortsExhausted** 和 **TcpMaxHalfOpen**：这两个值分别控制半开放连接的最大数量和端口耗尽的最大次数。

   路径: `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`

3. **EnableDeadGWDetect**：启用这个功能可以帮助检测和清理死网关的连接。

   路径: `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`

4. **SynAttackProtect**：开启这个功能可以帮助防止 SYN 洪水攻击，并且可以调整其级别。

   路径: `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters`

5. **TcpFastOpen**：启用快速打开功能，减少连接建立时间。

### 2.3 重置网络堆栈

如果更改参数无效，你还可以考虑重置网络堆栈：

1. 打开命令提示符（以管理员身份运行）。
2. 输入以下命令：
   ```
   netsh int ip reset c:\resetlog.txt
   ```
   这将重置网络配置到默认状态，并记录更改到指定的日志文件。

### 2.4 重启服务或应用程序

- **重启服务**：重启使用特定端口的服务或应用程序，这将关闭其连接并清理相关资源。

### 2.5 重启服务器

- **重启服务器**：作为最后手段，重启整个服务器可以清理所有连接状态，但这也意味着所有正在运行的服务将中断。

### 2.5 补丁

补丁**[KB2553549](https://thehotfixshare.net/board/index.php?/files/file/14355-windows61-kb2553549-v2-x64msu/)**。这个补丁主要解决了在 Windows Vista、Windows 7、Windows Server 2008 以及 Windows Server 2008 R2 系统中，当系统运行超过 497 天后，所有处于 TIME_WAIT 状态的 TCP/IP 端口不会被关闭的问题。

产生原因：
在 Windows 系统中，释放 TIME_WAIT 状态的 TCP 端点的时间是由当前系统运行时间加上 TIMEOUT 决定的，在没有打补丁的系统中，32 位寄存器中最多可以存放 0xFFFFFFFF，而存放在寄存器中的值是“时间\*0n100”，也就是说系统运行超过“0XFFFFFFFF/0n100”秒后就有可能出现 bug。
