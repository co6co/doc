# 1级
`Promise- new Promise(); Promise.resolve()`
时间系超能力不管在那个世界观里都是最强的一档，精准控制事件发生的顺序，还不会出现并发问题，同时完美契合数学结构；

解析赋值 `({a,b})=>{}; const {a,b}=item`
不敢想象以前的语法的多磨叽，体会不到它有多么优秀就是他最优秀的地方；

可选链 `item?.value`
现实世界充斥着可能的空缺，`?.` 就是最好的解药，虽然偶尔滥用，但绝大多数的时候，加上 `?.`问题就可以解决，而且本身就在数学上晚辈，拥有几乎不可能使问题变得严重的性质；

jsx `<div>{text}</div>`
不喜欢react的人有很多，而且很多点都说的有道理，但没有人不喜欢jsx，react的很大部分的开发体验都是 jsx提供的；

箭头函数 `(a,b)=>a+b`
这年头谁还用function，你说this?, 我就是不想要this

类型推断 `type User`
你写下的每一个类型都可以成为未来你写代码时的服务，没有类型的js只能被成为脚本，有类型后才能被成为工程，它是的开发加速成为了可能。

# 2级
const `const item={}`
const 给人一种安心感，唯一的缺点是五个字母翘起来繁琐，更短一些就更好了，要是默认就更好了，当然也只是梦里想想；

`async /await ` `const func =async (){await promise}`
Promise 提供了异步流程控制的可能的话，await 则大大提升了异步编程的体验，虽然await有传染性，但这不能说是await 的问题，async 则有一定的理解成本。

`spread /rest ` ` const {a,...rest}=item; const item={a,...rest}`
取值和赋值竟然如此自然，以至于你甚至意识不到这是两个语法.
主要问题是滥用，一层层的传递rest让人崩溃。但类型的存在阻止了这种面条代码导致的不可读。
所以要写类型，类型也会促使你把object作为原子，而不是各种揉捏。

`??` `value ??`
类似于`?.`好用但偶尔会掩盖错误。

# 3级
`import / export ` `import {Button} from 'antd'`
相当不错，但因为require的长期存在，两者转换实在是有点难，而且这货几乎总是与环境有关。webpack?node?浏览器?还有版本上的考虑.
`if else`  `for switch try/catch if(!value)`
基本语法

`as ` `as unknown as T`
很多人用类型体操来指责ts，殊不知ts是少见的不会强制对你指指点点的类型语言，这是ts值得赞赏之处，随时可以跳出，因为大部分时候开发不是搞数学证明

泛型 `<T>(value:T):T`
然而，ts同时又相当强大，允许你通过类型来证明代码的正确性。

模板字符串 `value:${value}`
js原生类型和原生方法 `arr.flatMap()`

flatMap 只是举个例，因为历史问题有少数方法稍不完美，但已经相当好用，不行还有 lodash 补充。 

`Proxy/Reflect` `new Proxy()`
写库会用（但是我也没用），vue 的核心，本质上 proxy 是语法糖，不知道各位 vue 吹能不能理解，并且 Proxy 作为语法糖是有限制的，也就是不能丢掉引用方，
所以 `.value = value` 和 `setValue(value) `在我看来也没有太大的区别。 

`Symbol` - `Symbol('foo')` 写库会用（但是我也没用），也是语法糖，没有它也有其他办法解决的。 

# 4级
`let` `let text = ''`
let 基本可以用 ref 来实现。 
`class` `class Class {}`
大部分情况是没有要用 class 的必要的，大部分程序员也没有用好 class 的能力，它们只是把所有东西塞到 this 里，然后让代码勉强可以跑起来而已。  
`generator`  `function* yield`
除了 llm 实在想不到什么场景。它的问题是总是一对一的匹配一个外部的处理机制，既然都匹配了，也就意味着用 await 也行。或者说一个 generator 必须至少有两种潜在的消费方式，才有被写成 generator 的价值。 

正则表达式  `/^\w+$/`
我估计所有人写 regex 都是能跑就行，而且 regex 好多方言，以前每次写都要重新学一遍，现在则是写几个 case 让 ai 生成个得了。 

`require`  `require('fs')`
require 本身还是挺好用的，没成为标准也不是它的错。
 复合赋值运算 `- a += 1; += -= *= /= ??= &&= ||=`
 语法糖，而且原地赋值现在也不常见。 
 
 `js-doc` ` /** @author me */ `
 纯文档，没有检验就会没法引起开发者的维护，经常看到没有价值的或者是过时的 jsdoc，哪怕是自己的库有时也会忘了改。
 
 `import with` ` import json from './a.json' with { type: 'json' }`
 还得靠环境来支持，库里写这个遇到问题，后来改方案了，感觉不可控。 
 
 装饰器  `@Get @Post` 兼容问题只是其次，最大问题还是说固定的抽象总是会遇到无法满足的例外，`@Get @Post` 这种除外。
 
# 5级
 
`var a `连 `let` 都不如。 

`extends`  `class A extends B`
屎山多种多样，但 extends 几乎总是导致屎山，人们总是为 extends 找到什么理由，但是绝大部分理由是不成立的，固定的抽象总是会遇到无法满足的例外。
你为一个类实现更多的东西，只会让它更难用。而继承更是把这个问题放大。 

enum  `enum COLOR { RED }` 
enum 基本可以认为是 ts 玩脱的产物，它是属于语言原则之外的东西，现在已经有开关可以关了，问题是还有很多人喜欢用。 

any  `(props: any)`
any 是好东西啊，大家都喜欢写 any，都不喜欢看 any。
如果你的想法是，这里需要一个 any 所以我写一个，这个我很赞赏，
但如果你的想法是，这里需要个类型而我不想写类型所以写个 any，这个是绝对错误的。
