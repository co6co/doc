# 1. 浏览器进程
浏览器是一个多进程多线程的应用程序，浏览器内部工作及其复杂，为了避免相互影响，减少连环崩溃的几率，当启动浏览器后，它会自动启动多个进程。
## 1.1 主要的进程
- 浏览器进程
  主要负责界面显示、用户交互、子进程管理等，浏览器进程内部会启动多个线程处理不同的任务
- 网络进程
  负责加载网络资源，网络进程内部会启动多个线程来处理不同的网络任务
- 渲染进程【开发是的重点进程】
  渲染进程启动后，会开启一个渲染主线程，负责执行HTML、CSS、JS代码。
  默认情况下，浏览器会为每个标签页开启一个新的渲染进程，以保证不同的标签也之间不相互影响。

  它是如何工作的（包括但不限于一下工作）：
      * 解析HTML
      * 解析CSS
      * 计算样式
      * 布局
      * 处理图层
      * 每秒刷新页面画面60次
      * 执行全局JS代码
      * 执行事件处理函数
      * 执行计时器的回调函数
      * .......

 ## 1.1.1 渲染进程
 为什么渲染进程不适合用多个线程来处理这些事情？
 
 要处理这么多任务，主线程该如何调度？
 > 排队
1. 一开始，渲染主线程会进入一个无线循环
2. 每一次循环会检查消息队列中是否有任务，如果有，就取出第一个任务执行，执行完一个后进入下一次循环，如果没有，则进入休眠状态；
3. 其他所有线程（包括其他进程的线程）可以随时向消息队列增加任务，新任务会加到消息队列的末尾。在增加新任务时，如果主线程是休眠状态，则会将其唤醒以继续循环拿去任务。

# 1.1.2 异步
- 计时完成后需要执行的任务 ---- setTimeout、setInterval
- 网络同学完成后需要执行的任务 ---- XHR、Fetch
- 用户操作后需要执行的任务  ----- addEventListener

使用异步的方式，渲染主线程永不阻塞：
> 如何理解JS的异步？
>
> JS是一门单线程的语言，这是因为他运行在浏览器的渲染主线程中，二渲染主线程只要一个，而渲染主线程承担这诸多工作，如渲染页面、执行JS；如果使用同步的方式，就极有可能导致主线程产生阻塞，从而导致消息队列中的很多其他任务无法得到执行。这样以来，一方面会导致繁忙的主线程拜拜的消耗时间，另一方面导致页面无法即使更新，给用户造成卡死现象。
> 所以浏览器采用异步方式来避免，具体做法是当某些任务发生时，比如计时器、网络、时间监听、主线程将任务交给其他线程去处理，自身立即结束任务的执行，转而执行后续代码。当其他线程完成时，将事先传递的回调函数包装成任务，加入到消息对立的末尾排队，等待主线程调度执行。
> 在这种异步模式下，浏览器永不阻塞，从而最大限度的保证了单线程的流畅运行。
>

# 2. 任务队列优先级
任务没有优先级，使用消息队列数据结构；但消息队列有优先级；
> 根据W3C的最新解释：
>  - 每个任务都有一个任务类型，同一类的任务必须放在一个队列，不同类型的任务可以属于相同的队列；再一次时间循环中，浏览器可以更具实际情况从不同的队列中取出任务执行；
>  - 浏览器必须准备好一个微队列，微队列中的任务优先所有其他任务执行；

目前在chrome的实际中，至少包含了下面的队列：
-  延时队列： 用于存放计时器到达后的回调任务【中】
-  交互队列： 用于存放用户操作后产生的时间处理任务【高】
-  微队列： 用于存放需要最快执行的任务【最高】

增加任务到微队列的主要方法是使用Premise、MulationObserver
```
//立即把一个函数增加到微队列
promise.resolve().then(fun)
```
## 2.1 代码
### 2.1.1 setTimeout函数
```
// 渲染线程 -- 执行全局JS代码
// 执行到 setTimeout 将告知其他线程计时,并继续执行后面的代码
// 其他线程及时结束，将setTimeout的回调函数封装为任务对象，放到延时队列中，
// 渲染线程执行完全局js，后从队列中按顺序取出任务执行。
// 返回结果为：2 1
setTimeout(function(){
    console.log(1)
},0);

console.log(2);
```
### 2.1.2 自定义延迟
```
/**
*  delay 是死循环3000ms 会卡3s钟
**/
setTimeout(function(){
    console.log(1)
},0);
delay(3000) 
console.log(2);
```
### 2.1.3 Promise
```
/***
* Promise 中的回调函数会放到微队列中，优先于延迟队列
* 结果为 3 2 1
***/
setTimeout(function(){
    console.log(1)
},0);
Promise.resolve().then(function(){
    console.log(2)
})
console.log(3);
```

### 2.1.4 混合
```
// 5 4 3 1 2
function a (){
     console.log(1);
     Promise.resolve().then(function(){
         console.log(2);
     })
}

setTimeout(function(){
    console.log(3);
    Promise.resolve().then(a);
},0)
Promise.resolve().then(function(){console.log(4)})
console.log(5)
```

# 3 JS中的事件循环
时间循环又叫消息队列，是浏览器渲染主线程的工作方式。
在Chrome的源码中，他开启一个不会结束的for循环，每次循环从消息队列中取出第一个任务执行，而其线程只需要在合适的时候将任务加到队列末尾即可；
过去吧消息队列简单分为宏队列和微队列，这种说法目前已无法满足复杂的浏览器环境，取而代之的是一种更加灵活多变的处理方式；
根据W3C官方解释，每个任务有不同的功能，同类型的任务必须在同一个队列，不同的任务可以属于不同的队列，不同的任务队列有不同的优先级，在一次事件循环中，由浏览器自行决定取哪一个队列的任务，但浏览器必须有一个微队列，微队列的任务一定具有最高的优先级，必须优先执行；
# 4. JS中的计时器能做到精确计时吗
不行，因为：
- 计算机硬件没有原子钟，无法做到精确计时；
- 操作系统的及时函数本身就有少量偏差，由于JS的计时器最终调用的是操作系统的函数，也就携带了这些偏差；
- 按照W3C的标准，浏览器实现计时器时，如果嵌套曾级超过5层，则会带有最少4毫秒的延迟；
- 受事件循环的影响，计时器的回调函数只能在主线程空闲时运行，因此又带来了偏差；

```
setTimeout(function(){
    setTimeout(function(){
         setTimeout(function(){
                     setTimeout(function(){
                        
                    },0)
            },0)
    },0)
},0)
```
