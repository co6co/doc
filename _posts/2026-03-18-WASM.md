# 1. rtsp

Real Time Streaming Protocol 本身并不定义或指定编码方式。它是一个网络控制协议，用于建立和控制媒体会话（如播放、暂停）。

视频流具体使用什么编码，是在RTSP会话的SDP（Session Description Protocol）描述中协商和声明的。因此，RTSP流理论上可以封装任何编码格式的视频和音频。

主流的视频编码格式：

- H.264/AVC(MPEG-4 Part 10)
  绝对的主流和默认选择，尤其是在安防监控、视频会议领域。
  在压缩率、画质和硬件支持度上取得了最佳平衡。几乎所有摄像头、NVR、流媒体服务器都支持生成H.264的RTSP流，客户端解码支持也最广泛。

- H.265/HEVC
  逐渐普及的下一代编码标准。在同等画质下，比H.264节省约50%的码流，但对硬件编解码性能要求更高。常见于较新的高端摄像头、超高清（4K/8K）流媒体场景。

- MPEG-4 (Part 2)
  较早期的标准，目前使用较少。 在H.264普及前被广泛使用，现在主要用于一些旧设备或特定系统。

- MJPEG (Motion JPEG)
  一种简单的帧内压缩格式，仍有特定应用。  
   每一帧都是独立的JPEG图片。优点是延迟极低、解码简单，缺点是压缩率低、带宽占用大。常用于对延迟要求苛刻的机器视觉或某些老式网络摄像头。

- VP8/VP9
  由Google主导的开源编码格式，在WebRTC中常见。RTSP流中相对少见，但部分支持WebRTC的设备或服务可能通过RTSP提供VPx编码的流。

# 2. 浏览器

浏览器原生不支持RTSP协议，在Web端（WASM环境）播放RTSP流通常需要：

- 后端转码/转协议：服务器端将RTSP流转换为浏览器支持的协议（如HLS、WebRTC、WS-FLV）。
- 前端WASM解码：如果要在浏览器内直接接收并解码RTSP码流（例如通过WebSocket），则需要WASM解码库（如FFmpeg.wasm）来支持相应的编码格式（主要是H.264）。

## 2.1 Emscripten

比较成熟是使用 FFmpeg（它内部集成了高质量的工业级解码器，如 libavcodec）通过 Emscripten​ 工具链编译为WASM

- FFmpeg.wasm (ffmpegwasm/ffmpeg.wasm) 功能完整，支持多种编解码器（H.264, HEVC, VP9, AV1等），既可以用于解码播放，也可以用于转码、处理等复杂操作

- VLC.js / libvlc-wasm
  基于著名的VLC媒体播放器，其核心也是 libavcodec。有项目将VLC的播放引擎编译为WASM
  提供了一个更偏向于“播放器”的完整解决方案，包括解码、音频输出、网络流处理等。适用于需要在Web端构建一个功能接近原生VLC播放器的场景
- Jyane（贾言） / Broadway
  一个专注于 H.264 Baseline Profile​ 的纯JavaScript + WebAssembly/WebGL解码器
  比较适用于需要低延迟解码H.264 Baseline视频流的应用，例如视频会议、监控画面

## 2.2 封装

1. 选择解码器核心：通常选择 libavcodec（来自FFmpeg）或者 openh264（Cisco开源，仅H.264
2. 使用Emscripten进行编译：
   - 配置Emscripten环境。

   - 编写或调整编译脚本，将解码器C/C++源码以及必要的胶水代码编译为 .wasm文件和 .js胶水代码。

   - 关键配置：需要禁用文件系统、网络等不必要的依赖，并正确导出供JavaScript调用的函数（如 decode， createDecoder， destroyDecoder）。

3. 编写JavaScript接口层：
   - 加载WASM模块。
   - 提供易用的API，接收ArrayBuffer类型的视频数据，调用WASM解码函数。
   - 将WASM解码输出的YUV数据通过Canvas 2D或WebGL渲染到屏幕上。
4. 处理音频（如果需要）通常需要单独编译音频解码器（如 libavcodec中的AAC解码器），并通过Web Audio API播放。

# 3. web 浏览器播放 rtsp视频的方案

1. 后端拉取 RTSP 流 （后端拥有完整的网络栈，可以处理 RTSP/TCP/UDP）
   使用原生 FFmpeg 或 libavformat连接摄像头 RTSP 流
2. 转换协议并通过 WebSocket 转发
   - 后端将 RTSP 流解封装，提取出视频裸流（如 H.264 NALU），通过 WebSocket​ 发送给浏览器。
   - 或者转换为浏览器友好的协议，如 HTTP-FLV、HLS、WebRTC。
3. 前端 WASM 解码
   - 浏览器通过 WebSocket 收到视频数据后，调用 WASM 封装的 FFmpeg 进行解码。
   - 将解码后的 YUV/RGB 数据用 Canvas/WebGL 渲染

```
// 1. 建立WebSocket连接
const ws = new WebSocket('ws://localhost:9999');
const ffmpeg = await createFFmpeg({ log: true });

ws.onmessage = async (event) => {
  // 2. 接收到数据（假设是H.264 NALU）
  const data = new Uint8Array(await event.data.arrayBuffer());

  // 3. 使用ffmpeg.wasm解码
  ffmpeg.FS('writeFile', 'input.h264', data);
  await ffmpeg.run('-i', 'input.h264', '-f', 'rawvideo', 'output.yuv');
  const yuvData = ffmpeg.FS('readFile', 'output.yuv');

  // 4. 渲染到Canvas
  renderYUVToCanvas(yuvData, width, height);
};
```

## 3.1 其他方案

方案一. RTSP 转 HLS/HTTP-FLV + 标准播放器（推荐）：

- 后端：用 nginx-rtmp-module、SRS、ZLMediaKit等将 RTSP 转 HLS/HTTP-FLV。
- 前端：用 hls.js、flv.js等标准播放器直接播放。

方案二. 纯 Web 方案（WebRTC 转发）：

- 使用 Janus Gateway​ 或 Mediasoup​ 将 RTSP 流转换为 WebRTC 流。
- 浏览器直接用 video 标签播放（WebRTC 原生支持）。

方案三： ffmpeg.wasm + WebSocket 的完整播放器：
已有项目如 Broadway（H.264 解码）或基于 ffmpeg.wasm 的自定义播放器，配合 WebSocket 传输。

## 4.1 载入 wasm的方式

```
// WASM的加载和执行流程
async function loadWasm() {
  // 1. 获取.wasm二进制文件
  const response = await fetch('module.wasm');
  const buffer = await response.arrayBuffer();

  // 2. 编译和实例化
  const module = await WebAssembly.compile(buffer);
  const instance = await WebAssembly.instantiate(module, {
    // 导入的对象（如JavaScript函数、内存等）
    env: {
      memory: new WebAssembly.Memory({ initial: 256 }),
      table: new WebAssembly.Table({ initial: 0, element: 'anyfunc' })
    }
  });

  // 3. 执行导出的函数
  const result = instance.exports.add(1, 2);
  console.log(result); // 3

  return instance;
}
```

## 4.2 浏览器是否支持

```
if (typeof WebAssembly !== 'undefined') {
  // 现代浏览器：使用WASM
  fetch('module.wasm')
    .then(response => response.arrayBuffer())
    .then(instantiateWasm);
} else {
  // 旧浏览器：回退到asm.js或纯JavaScript
  const script = document.createElement('script');
  script.src = 'module.asm.js';  // 同一代码编译的asm.js版本
  document.head.appendChild(script);
}
```

## 4.3 wasm 其他应用

### 4.3.1 密码学与加密

- 避免JavaScript内存中的密钥被XSS攻击窃取
- 可集成硬件级安全（如WebCrypto API补充）

```cpp
// 在WASM中实现加密算法（避免JavaScript内存暴露）
#include "openssl/aes.h"

EMSCRIPTEN_KEEPALIVE
void aes_encrypt(const uint8_t* input, uint8_t* output, const uint8_t* key) {
    AES_KEY aes_key;
    AES_set_encrypt_key(key, 128, &aes_key);
    AES_encrypt(input, output, &aes_key);
}
```

### 4.3.2 代码混淆与保护

```
// 用Rust编译WASM保护核心算法
#[wasm_bindgen]
pub struct SecureProcessor {
    secret_key: [u8; 32],
}

#[wasm_bindgen]
impl SecureProcessor {
    pub fn process_sensitive_data(&self, data: &[u8]) -> Vec<u8> {
        // 核心业务逻辑，难以逆向
        data.iter().map(|x| x ^ self.secret_key[x as usize % 32]).collect()
    }
}
```
