# 1. 实体和类的区别

# 2. Essenial Use Cases 与 Real Use Cases
  Real Use Cases 【基础用例】是通过调研用户需求而获得的，与用户需求有对于关系的用例，而能从两个或两个以上基础用例提取公共行为时，把提取出来的公共用例称Essenial Use Case【抽象用例】

# 3. 内存数据库
	分布式数据库缓存是内存种管理数据并提高数据的一致性保障，采用数据复制技术实现高可用性，具有较优的扩展性与性能组合。
	这种数据缓存机制，实现了更短的响应时间，同时极大地降低数据库的十五处理负载，极好的解决大流量情况下数据库服务器和Web服务器之间的瓶颈。
	
	Memcache不支持数据持久化操作，所有掉电后数据全部会丢失，而且无法直接恢复，这存在可靠性问题；
	Memechce 不支持事务，所有操作过程种可能产生数据的不一致性；
	
	使用Redis**同步方案**：先读取Redis种的数据，如果Redis没有，则从原数据库种读取，
	并同步更新Redis种的数据； 写回时，写入到原数据库种，并同步更新到Redis中.
	
	Redis 分布式**存储的2种常见方案**：redis 主从方案、redis cluster方案；
	
	Redis 集群切片常见方式：
		- 客户端分片： 在客户端通过key的hash值对应到不同服务器。
		- 对数据 key散列到不同的slot上，不同的slot对应不同的服务器；

# 4. SOA 面向服务的架构
	SOA是一个组件模型，它将应用程序的不同功能单元（称服务）通过这些服务之间定义良好的接口和锲约联系起来。
	接口是采用中立的方式定义的，他独立于实现服务的硬件平台、操作系统和编程语言，这使得构建在各种各样的系统种的服务可以以一种同一和同一的方式进行交互。
	
	- 支持SOA的关键是其消息传递架构--企业服务总线-ESB
		ESB用于实现企业应用不同消息和信息的准确、高效和安全的传递；
	- 面向服务的元数据管理
		必须了解被他中介的两端，即服务的请求以及请求者对服务的要求，以及服务的提供者和他所提供的服务的描述；
	- 通讯 服务的发布/订阅、响应/请求、同步/异步消息、路由	和寻址等
	- 服务交互：服务接口定义，服务实现的置换，服务消息模型，		服务目录和发现等。
	- 服务安全：认证和授权、不可否认和机密性、安全标准的支持；
	
	安全服务策略：
	1.采用挑战/应答的认证机制，防止重放攻击。
	2.采用加密技术保证信息在网络传输过程的安全。
	2.采用数字签名技术保证信息传输过程的完整性和不可否认。
